# 🚀 PatchPilot — Frontend

**The web interface for PatchPilot, an AI-powered open-source onboarding assistant.**

PatchPilot helps developers explore GitHub repositories, understand unfamiliar code through beginner-friendly explanations, and discover potential open-source contribution opportunities.

This repository contains the frontend application, built with Next.js and React, designed to communicate with the PatchPilot backend for repository data and AI-powered features.

## ✨ Features

- **Repository Dashboard** — View repository information and explore project structure.
- **Code Explorer** — Navigate source files and inspect code.
- **AI-Powered Explanations** — Display beginner-friendly code explanations generated by the backend.
- **Interactive Code Q&A** — Ask questions about repository code.
- **Contribution Finder** — Explore potential contribution opportunities backed by repository evidence.
- **Responsive Interface** — A modern interface designed for different screen sizes.
- **Backend Integration** — Connect to the PatchPilot API for live repository analysis.

*Feature availability depends on the corresponding backend endpoints being configured and operational.*

## ⚙️ Getting Started

### Prerequisites

Install the following before running the frontend:

- [Node.js](https://nodejs.org/) — use a version supported by your installed Next.js version.
- npm — included with Node.js.
- A running PatchPilot backend, if you want to use live repository analysis and AI features.

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY/patchpilot-frontend
```

Replace the example repository URL with your actual GitHub repository URL.

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment variables

Create a local `.env.local` file in the `patchpilot-frontend` directory.

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

This URL assumes the FastAPI backend is running locally on port `8000`.

For production, set `NEXT_PUBLIC_API_BASE_URL` to your actual deployed backend URL, such as:

```env
NEXT_PUBLIC_API_BASE_URL=https://your-backend-domain.example.com
```

Replace the example domain with your real backend URL. Do not add a trailing slash unless your API configuration expects one.

**Security:** Only use `NEXT_PUBLIC_` variables for values that are safe to expose in the browser. Never place Gemma API keys, GitHub tokens, or other secrets in frontend environment variables.

### 4. Start the development server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## 🔌 Backend & API Integration

The frontend communicates with the PatchPilot backend over HTTP.

The backend is responsible for:

- Fetching repository metadata and files from GitHub.
- Requesting AI-generated explanations from the configured Gemma API.
- Processing repository-related questions.
- Providing contribution suggestions supported by repository evidence.

The frontend does not need direct access to the Gemma API key. AI requests should pass through the backend.

If the website displays **"Unable to load repository data"**, check that:

1. The backend is deployed and reachable.
2. `NEXT_PUBLIC_API_BASE_URL` points to the correct backend URL.
3. The backend exposes the endpoints expected by the frontend.
4. CORS allows requests from the deployed frontend domain.
5. The frontend has been rebuilt and redeployed after environment-variable changes.

## 🚀 Deployment

### Deploy with Vercel

1. Push your project to GitHub.
2. Import the repository into [Vercel](https://vercel.com/).
3. Set the **Root Directory** to `patchpilot-frontend` if this folder is inside a monorepo and contains the frontend's `package.json`.
4. Configure `NEXT_PUBLIC_API_BASE_URL` in the project's environment variables.
5. Deploy the application.
6. Test repository loading, code explanations, and other backend-dependent features.

The FastAPI backend must also be deployed to a reachable hosting environment. Deploying the frontend alone does not make the backend available.

## 🔐 Security & Reliability

- Keep private API credentials on the backend.
- Do not commit local environment files containing secrets.
- Validate and handle backend errors gracefully.
- Treat AI-generated explanations and contribution suggestions as recommendations that should be checked against the actual source code.
- Never execute arbitrary repository code simply to analyze it.

## 🎯 Project Goal

PatchPilot aims to make open-source development more approachable for students and beginner developers by simplifying code exploration, explaining unfamiliar projects, and helping users find meaningful ways to contribute.
